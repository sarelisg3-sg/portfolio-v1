<Callout title="Scope">
Independent redesign of the resource search-and-download flow. The prototype covers that flow end to end; other sections of the site are out of scope for this iteration.
</Callout>

## The problem

**Le Point du FLE** is a free directory of resources for learning and teaching French as a foreign language: thousands of materials organised by topic, level and activity type. The content is valuable; the structure isn't. Sprawling categories, vague link titles and paths with no hierarchy force users through too many pages before reaching a relevant resource.

A **heuristic evaluation** (Nielsen's 10 principles) of the existing site surfaced 9 problems — 4 of them at maximum severity:

- Too much visible information and an unclear visual hierarchy.
- Broad, redundant categories.
- Hard to locate resources by level.
- No clear paths for teachers and students.

**Impact:** teachers and students waste time hunting for materials, doubt whether what they find is relevant, and abandon the search. For the platform: lower return visits, higher drop-off and migration to better-organised competitors.

## Findings and insights

| # | Insight | Evidence |
|---|---|---|
| **I1** | Users search from pedagogical needs (level, skill, topic), not from the site's structure. | Survey · Journey map · Tree testing |
| **I2** | The architecture demands too much cognitive effort to locate materials. | Tree testing: 70% error · Heuristics |
| **I3** | Filters are essential to reduce search time and effort. | Survey · Identified needs |
| **I4** | Classifying by level / skill / type matches the user's mental model. | Survey · Identified profile |
| **I5** | More guided navigation raises confidence and eases discovery. | Heuristics · Tree testing · Journey map |

**Working hypothesis:** if resources are organised by level, skill and type, and filters are visible and functional, users will find materials faster, with less cognitive effort and more confidence in their choice.

## Design decisions

| Decision | Why |
|---|---|
| **D1 · Navigation structured by level (A1–B2)** | Users mentally organise resources by learning level. |
| **D2 · Filters by type, skill and topic** | They need mechanisms to cut down the volume of information. |
| **D3 · Search as the main entry point** | Direct access without relying on extensive browsing. |
| **D4 · Reorganise the information architecture** | Research showed difficulty identifying clear paths. |
| **D5 · Clearer, more consistent visual hierarchy** | An organised visual structure reduces cognitive load. |
| **D6 · Visible metadata per resource (level, type, skill)** | Users need to quickly judge whether a resource fits. |

## 15 evidence-based iterations

Every change answers something observed in the sessions, not a preference:

| # | Change | What prompted it |
|---|---|---|
| 1 | Less hero spacing | *Content peeking*: users didn't see content below the search box. |
| 2 | A2 card turned into a navigable link | *False affordance*: it looked clickable but did nothing. |
| 3 | Results consistent with “passé composé A2” | Consistency between the search term and the results shown. |
| 4 | Level fixed from B1 to A2 on a card | Level accuracy: critical for teachers. |
| 5 | Pagination and results counter | Orientation: users wanted to know how many resources there are. |
| 6 | Filters with working dropdowns | Decorative filters caused frustration and loss of trust. |
| 7 | “Compréhension orale” → “Document sonore” | Separate language skill from resource format. |
| 8 | From 3 cards to 15 results | Consistent with “15 résultats par page” and better exploration. |
| 9 | New A2 level page | Natural path: users expected to browse by level first. |
| 10 | Contextual search inside A2 | Respect more than one search mental model. |
| 11 | Filters on A2 without the level filter | Minimalism: the level filter was redundant inside A2. |
| 12 | 15 varied cards on A2 | Variety of formats improves the site's value proposition. |
| 13 | Removed the duplicate “Télécharger” button | Hick's law: duplicate CTAs create ambiguity. |
| 14 | “Source” accordion with author and organisation | Transparency: users want to know where the material comes from. |
| 15 | Modal with the real PDF when opening the file | Closes the action loop and confirms the downloaded resource. |

**Before → after:** A2 card with no action → level page · inconsistent results → consistent with the search · decorative filters → dropdowns with active states · 3 results → 15 · two download buttons → one contextual CTA · no source → accordion with author · no preview → real embedded PDF.

## Learnings and next steps

The iterations proved that **a solution doesn't work just because it looks clear**: the filters “looked” fine and still caused frustration because they didn't respond. Every design decision must answer an observed need, a real behaviour or a testable hypothesis.

**Next steps:**

- A second round of usability testing on the iterated prototype, measuring whether wrong clicks and search time go down.
- Explore favourites or folders for teachers.
- Expand the related-resources recommendation system.
- Validate visual accessibility and responsive navigation.
- Define real usage metrics for the next implementation phase.
